## Edge Assumptions (no SPEC.md for this phase)

- The spike identity is one fixed account (`SPIKE_ACCOUNT_EMAIL`, default `porteur@relay.invalid`, a placeholder on the reserved .invalid domain); every Claude the owner connects binds to it. KV `userId` = `spike_` + first 24 hex chars of SHA-256(`relay-spike:` + lowercased label).
- Grant props are exactly `{ userId, authorizedAt }`. The label shown to the user is never stored with the grant: `resolveSpikeAccount(env, userId)` recomputes `spikeUserId(env.SPIKE_ACCOUNT_EMAIL)` at request time and returns the label only when it matches. In phase 2 the same seam reads the account from the EU D1 users table instead of configuration.
- `SPIKE_ACCESS_CODE` shorter than 16 characters, or absent, refuses every approval (fail-closed). Wrong code re-renders the page with HTTP 400 and does not consume the consent handle.
- Scopes: the page grants the requested scopes intersected with `mcp:tools` and `offline_access`; the MCP handler does not enforce scopes in phase 1 (advertised only, per library docs).
- Access tokens live 900 s in the spike so that real Claude refreshes during a session; refresh grants keep the library default (30 days).
- GET and DELETE on `/mcp` are answered by the SDK stateless legacy leg (405); that is expected, not a failure.
- Requests to `/mcp` whose Host header is not the `PUBLIC_BASE_URL` host are refused before the SDK; requests without an Origin header are allowed (Anthropic's cloud sends none).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet (Anthropic cloud 160.79.104.0/21, any client) → /mcp, /register, /token, /.well-known/* | Untrusted requests; bearer tokens and client metadata cross here |
| Owner's browser → /authorize | Consent form; attacker-chosen client names (DCR / CIMD) are rendered here |
| Worker → OAUTH_KV | Global KV store (not EU-restrictable): grants, hashed tokens, encrypted props |
| Worker → console / wrangler tail | Anything logged leaves the request; must be metadata only |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Spoofing | /mcp (mcpApiHandler) | high | mitigate | OAuthProvider validates the bearer and its audience before apiHandler runs; unauthenticated calls get a real 401 + resource_metadata challenge (smoke step 1 here, conformance tests in plan 03) |
| T-01-02 | Elevation of privilege | /authorize spike approval | high | mitigate | approval requires SPIKE_ACCESS_CODE (>= 16 chars, SHA-256 + crypto.subtle.timingSafeEqual, fail-closed when unset) checked before approveConsent (src/spike/identity.ts, src/authorize.tsx) |
| T-01-03 | Tampering | consent form (CSRF, clickjacking) | high | mitigate | beginConsent/approveConsent handle bound to a __Host- cookie, single use, 10 min; consent.headers plus CSP frame-ancestors 'none' |
| T-01-04 | Tampering | redirect_uri / code interception | high | mitigate | parseAuthRequest exact redirect validation (loopback port only flexibility), PKCE S256 mandatory; edge cases asserted in plan 03 |
| T-01-05 | Information disclosure | logs (src/log.ts, onError, mcp handler) | high | mitigate | plan-01 whitelist seam, onError logs code/status/reason only, handler logs argBytes never arguments or props, canary assertions in the tracer test |
| T-01-06 | Tampering (XSS) | consent page rendering client metadata | high | mitigate | hono/jsx auto-escaping, no raw HTML insertion, CSP default-src 'none', escaped plain-text error pages |
| T-01-07 | Information disclosure | OAUTH_KV (global, not EU) | high | mitigate | props restricted to SpikePropsSchema { userId, authorizedAt } (strict at write in authorize.tsx and at read in handler.ts), grant userId opaque hash of a .invalid placeholder label, metadata { kind: "spike" }, label resolved at request time from configuration; tracer test scans every KV value for the canary |
| T-01-08 | Spoofing | account confusion (a Claude bound to the wrong inbox) | medium | mitigate | consent page names the linked account in plain text; ping echoes the account so the user sees it in Claude; unknown userId yields « Compte inconnu »; real defense lands with AUTH-03 in phase 2 |
| T-01-09 | Spoofing | Host header / DNS rebinding on /mcp | low | mitigate | hostHeaderValidationResponse against the PUBLIC_BASE_URL host, foreign Origin refused |
| T-01-10 | Denial of service | oversized /mcp bodies | low | accept | SDK maxRequestBodySize default 4 MiB plus Cloudflare request limits; no data at risk in the spike |
| T-01-11 | Repudiation | who authorized which client | low | mitigate | authorize_decision event with decision and clientKind, no personal data |
